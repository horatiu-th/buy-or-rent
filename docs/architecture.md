# Architecture

A static single-page app: Vite + React 19 + TypeScript, charts with Recharts, tests with Vitest and Testing Library. There is no backend. Default data is merged at build time and bundled into the page.

## How data flows

```
data/overrides.json ─┐
                     ├─ npm run data:merge ─► src/data/defaults.json   (bundled at build)
data/auto.json ──────┘                                │
                                                      ▼
URL query string ◄──► Scenario (city, type, m², currency, view, edited values)
                                                      │
          resolveInputs(defaults, city, type, m², edited values)
                                                      ▼
                                                   Inputs
                                                      │  useDeferredValue
                                                      ▼
  simulate() · equivalentRent() · horizonComparison() · sensitivity() · assumptionSwings()
                                                      ▼
        Headline · RentScale · EndSummary · HorizonTable · charts · tables
```

1. **Defaults** come from `src/data/defaults.json`, imported directly so there is no loading state.
2. **The scenario** holds what the user chose: city, property type, size, currency, today's-money vs nominal, and any values they edited. It lives in the URL, so every scenario is a shareable link.
3. **Inputs** are the city defaults with the user's edits on top. Property and rent growth, the investment return and the long-run IRCC default to inflation plus a real part, so an edited inflation moves them too unless they were edited themselves.
4. **The engine** turns inputs into results. Typing stays smooth because results render from a deferred copy of the inputs and the results panel is memoized.

## Folders

### `src/engine/`: the calculation

Pure functions, no React, no I/O. See [How the calculation works](how-it-works.md) for the model.

| File | Purpose |
|---|---|
| `types.ts` | `Inputs`, `MonthRow`, `Result` and the totals types |
| `sanitize.ts` | Replaces non-finite inputs and clamps and rounds them into the range the model is defined for; exports the horizon and loan-term limits |
| `mortgage.ts` | `annuityPayment()` and `amortize()` with the fixed-to-variable switch |
| `costs.ts` | Acquisition costs (including the notary's mortgage-contract scale) and sale costs |
| `simulate.ts` | The month-by-month simulation, renter moves and the break-even month |
| `solve.ts` | Equivalent rent (bisection), the verdict at several horizons, the sensitivity grid and the one-at-a-time assumption swings |
| `index.ts` | Public API of the engine |
| `fixtures.ts` | Shared test inputs (`baseInputs`, `flatWorld`) |

All money is in lei; all rates are decimals (`0.055` = 5.5%). Currency conversion and display rounding happen only in the UI.

### `src/data/`: defaults

| File | Purpose |
|---|---|
| `schema.ts` | `SourcedValue` (value + unit + source + date + status), the data file types, and the list of required keys |
| `defaults.json` | Generated by `npm run data:merge`. Don't edit by hand; see [Data](data.md). |
| `defaults.ts` | `buildInputs()` turns city €/m² × size × exchange rate into a price (less the negotiation margin) and a rent (the rent index's own yield applied to that price, scaled by `rentForSize()`), sets property tax per m², derives the inflation-linked rates, and fills every other input. `resolveInputs()` puts the user's edits on top. `sourceFor()` finds the source shown in each field's info popover. |

### `src/state/`: the scenario

| File | Purpose |
|---|---|
| `scenario.ts` | `DEFAULT_SCENARIO`, and `encodeScenario()` / `decodeScenario()` to and from the URL |
| `useScenario.ts` | React hook: reads the URL once, writes it back on every change with `replaceState`, and exposes `update`, `setField`, `resetField`, `resetAll` |

**URL format.** Only values that differ from the defaults are written.

| Parameter | Meaning |
|---|---|
| `oras` | City id (`bucuresti`, `cluj`, …, `ro` for the national average). Unknown ids are ignored. |
| `tip` | No longer used; ignored in older links |
| `mp` | Size in m², clamped to 10–500 |
| `moneda` | `EUR` (lei is the default) |
| `real` | `0` for nominal values (today's money is the default) |
| any `Inputs` key | An edited value, e.g. `rent=2500`, `fixedYears=0`, `includeSaleCosts=0`. Numbers are clamped to the field's range; booleans accept only `0` and `1`. |

Changing city, type or size drops edited price, rent and property tax, since they describe the home; other edits stay. "Resetează tot" (reset all) clears everything.

### `src/ui/`: components

| File | Purpose |
|---|---|
| `fields.ts` | One definition per input: unit (`money`, `pct`, `years`, `months`, `bool`), topic, and min/max/step |
| `InputsPanel.tsx` | Arranges fields into collapsible groups: Cumpărare and Închiriere. The general fields (horizon, inflation) sit in the scenario strip next to the city and size instead, rendered by `App.tsx`. Închiriere lists rent and investment fields together under a single heading. Buying costs and sale settings fold under a further toggle. Collapsed groups count the edits inside them. |
| `InputField.tsx` | One input: a text draft while typing, conversion for % and €, a ↺ reset when edited, and an info popover with the explanation and the source |
| `CityPicker.tsx` | The city, property type and size row |
| `Segmented.tsx` | Radio group drawn as a segmented control |
| `Results.tsx` | Runs the engine and lays out the results: headline, rent scale, end-of-horizon figures, the horizon table, tabs |
| `Headline.tsx` | The verdict sentence and the break-even line |
| `RentScale.tsx` | The draggable bar comparing your rent with the break-even rent |
| `charts.tsx` | Net worth, monthly costs and breakdown charts, with a shared tooltip |
| `SensitivityTable.tsx` | The ±2 percentage point grid, and `SwingsTable`: rent, rent growth, long-run IRCC and upkeep rate moved one at a time |
| `HorizonTable.tsx` | The rent threshold and net-worth gap at 5, 10, 20 and 30 years and the chosen horizon |
| `format.ts` | Money and duration formatting in Romanian |

### `src/i18n/ro.ts`: all text

Every string shown in the interface is here, including each field's label and help text. The `fields` map is type-checked against `Inputs`, so adding an input without its text is a compile error.

### `src/styles.css`: the look

One stylesheet with design tokens at the top, in light and dark variants:

| Token | Use |
|---|---|
| `--buyer` | Blue: the buyer, and the Cumpărare group |
| `--renter` | Teal: the renter across all charts and the Închiriere group |
| `--paper`, `--surface`, `--ink`, `--muted`, `--line`, `--field` | Background, text and line colours |

The typeface is Schibsted Grotesk, bundled with the app (no external font requests). On desktop the results column stays in view while the inputs scroll; on narrow screens results come first.

### `pipeline/`: data scripts

Run with `tsx`. See [Data](data.md).

| File | Purpose |
|---|---|
| `run.ts` | Runs every fetcher, writes `data/auto.json` and a summary |
| `runFetchers.ts` | Validates each fetched value; keeps the previous one and marks it `stale` on failure |
| `validate.ts` | Range check and a "changed more than 30%" check |
| `fetchers/` | One module per source (currently the BNR exchange rate) |
| `http.ts` | `fetchText()` with a generic user agent and a 15-second timeout |
| `merge.ts`, `mergeData.ts` | Combines `auto.json` and `overrides.json` into `src/data/defaults.json` |

## Common changes

### Add an input

1. Add the field to `Inputs` in `src/engine/types.ts` and use it in the engine, with a test.
2. If it can go out of range, clamp it in `sanitize.ts`.
3. Add it to `fixtures.ts`.
4. Add its definition to `FIELDS` in `src/ui/fields.ts` (unit, topic, limits).
5. Add its label and help text to `ro.fields` in `src/i18n/ro.ts`.
6. Add it to `REQUIRED_VALUE_KEYS` in `src/data/schema.ts` and to `buildInputs()` in `src/data/defaults.ts`.
7. Add a sourced default to `data/overrides.json`, document it in `data/SOURCES.md`, and run `npm run data:merge`.

TypeScript will point out most places you miss.

### Add a city

Add an entry under `cities` in `data/overrides.json` with `name`, `priceSqmEur`, `rentSqmEur` and `rentPriceSqmEur` (the sale €/m² from the same index as the rent), document the source in `data/SOURCES.md`, then run `npm run data:merge`. The city picker lists every city in the data automatically.

### Change interface text

Edit `src/i18n/ro.ts`. Some UI tests find elements by their Romanian labels; update them if you rename one.

## Testing

```bash
npm test             # everything
npm run test:watch   # watch mode
```

| Area | What the tests cover |
|---|---|
| Engine | Invariants, the loan schedule, the solver, input clamping, reference snapshots |
| Data | Merging, required keys, `buildInputs()` |
| Pipeline | Validation, stale fallback, the BNR parser against a saved copy of the real feed |
| State | URL round trips, defaults, malformed and out-of-range values |
| UI | City change updates the verdict, edits reach the URL, links restore state, presets, the rent slider, collapsible groups, info popovers, the footer |

Tests never touch the network: fetchers are tested against files in `pipeline/fixtures/`.

If Vitest reports a module it can't find right after you create it, clear its cache with `npx vitest --clearCache`.

## Conventions

- For ticket work, name branches `<type>/<ticket>-<short-kebab-description>`.
- For ticket work, use a single-line commit message in the form `<type> #<ticket>: <what changed>`.
- Comments explain non-obvious reasons, not what the code does, and never mention ticket numbers.
- Interface text is Romanian; code, comments and documentation are English.
